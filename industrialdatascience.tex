\section{工业数据科学}

\subsection{引言}

工业数据科学听起来是个很大的词，但落到实处，它要回答的问题其实很具体：工厂里天天产生海量数据，怎么才能把这些数据变成能帮工厂省钱、提质、避免风险的东西？我们借一个真实的工业案例：喷油器（Injektor）的质量检测，来把这件事从头到尾讲一遍，你会发现整个过程其实有一套很清晰的方法论可以照着走。

数据科学早就不是什么遥远的黑科技了。剑桥分析（Cambridge Analytica）通过分析社交媒体数据，为美国每一个成年人建立性格和行为的预测模型，再据此推送定制化的政治宣传信息去影响投票。所以数据科学是一把双刃剑，用得不好会带来严重的伦理问题。而另一面，亚马逊、微软、苹果的语音助手靠自然语言识别和处理运作，DeepL 的机器翻译靠深度学习训练的神经网络运作。这些早就悄悄嵌进了我们每天用的产品里。

理解数据分析能做到什么程度，常用一条从低到高的价值线：
\begin{itemize}
    \item 描述性分析（Descriptive）：回答发生了什么，是最基础的观察和统计
    \item 诊断性分析（Diagnostic）：回答为什么会发生，需要解释原因
    \item 预测性分析（Predictive）：回答接下来会发生什么，需要对未来做预判
    \item 规范性分析（Prescriptive）：回答应该怎么做，直接给出行动建议
\end{itemize}
往后走，能带来的业务价值越大，技术难度也越高。喷油器案例做的正是"预测性分析"，这条线索会贯穿全文。

两个直观的数字可以补充说明数据规模的增长：全球每年产生的数字数据量预计从 2005 年的 130 艾字节，一路涨到 2025 年的 175,000 艾字节，年增长率约 30\%；企业自己产生的数据占比也会从 2015 年的 30\% 涨到 2025 年预计的 60\%。

描述这类海量、复杂数据的特征，通常用\textbf{大数据领域常说的3V}：
\begin{itemize}
    \item Volume（容量）
    \item Velocity（速度）
    \item Variety（多样性）
\end{itemize}
数据量级从太字节到泽字节不等，有批量处理的也有实时产生的数据流，结构化、非结构化、半结构化数据混杂在一起。至于工具，2014 年的一份行业调查显示，RapidMiner、R、Excel、SQL、Python 是当时最常用的几款，具体排名会随时代变化，留个印象即可。

\subsection{CRISP-DM}

接下来用一套业界通用的方法论 \textbf{CRISP-DM（Cross-Industry Standard Process for Data Mining，跨行业数据挖掘标准流程）}把喷油器案例串起来。这套方法论把一个完整的数据科学项目拆成六个阶段：
\begin{enumerate}
    \item \textbf{业务理解（Business Understanding）}：搞清楚项目到底要解决什么问题
    \item \textbf{数据理解（Data Understanding）}：搞清楚手头有什么数据、质量如何
    \item \textbf{数据准备（Data Preparation）}：把原始数据加工成能喂给模型的形式
    \item \textbf{建模（Modeling）}：选择合适的算法，训练模型
    \item \textbf{评估（Evaluation）}：判断模型到底好不好用
    \item \textbf{部署（Deployment）}：把模型真正用到实际生产决策中去
\end{enumerate}
这六个阶段不是一次性走完就结束的直线流程，而是一个可以循环迭代的闭环。评估阶段发现问题，往往要回头重新做数据准备甚至业务理解。

\paragraph{示例：喷油器的质量检测瓶颈}

喷油器的生产分为部件加工和总装两大部分。总装线上要经历“压装滤芯和密封圈→安装增压器→拧紧增压器螺栓→拧紧控制模块螺栓→拧紧喷射模块螺栓→密封性检测”等一连串工序，最后要经过一套完整的液压终检。这是一种 100\% 全检，每个产品要在多个检测点（P1、P2……）上分别测量喷射量、压力、回流量等多项特性，再和规格比对，最终打上合格标签。

问题在于，这种全检非常耗时，成了整条生产线的瓶颈工序。项目要解决的目标很明确：通过数据分析提前预测最终检测点的结果，从而减轻检测环节的压力。这正是一个典型的预测性分析任务。装配和检测过程中会记录超过 120 个参数，这些就是后续建模的原始素材。

工厂里的数据并不集中存在一个地方，而是按照一个金字塔式的层级分布：最底层是传感器和执行器（现场层），往上依次是 PLC 控制层、SCADA 过程控制层、MES 生产执行层，最顶层是 ERP 企业管理层。越往下的数据实时性越强、粒度越细；越往上的数据越偏向管理和计划。这个分层模型来自 VDI/VDE 2013 年的标准，是理解工厂信息系统结构时常用的参照。

针对喷油器项目，数据通过 OPC UA、平面文件、ODBC 等不同格式从机器端采集，再经由解析器和 ETL（抽取-转换-加载）流程、通过消息中间层汇总进 MES 数据库（比如 Oracle、MySQL、MSSQL）。之后再用一条 SQL 查询，针对特定的故障模式和零件编号，抽取一份有代表性的样本，形成建模用的原始数据表。

正式建模之前，还需要一轮描述性和探索性分析：通过统计和可视化手段先摸清楚数据的分布情况，为后面选方法、调参数打好基础。多数学习算法都要求数据整理成规整的表格结构：每一行是一个样本（对象），每一列是一个特征（属性）。

拿到原始数据后，往往不能直接拿去训练模型，通常要先完成几件事：
\begin{itemize}
    \item 数据清洗：识别并处理错误、无关、重复或缺失的数值。
    \item 数据变换：不同的数据往往处在不同的量纲层级上。很多学习算法要求所有输入特征处在统一的量纲层级上，建模前往往需要做升级或降级处理，让不同类型的数据能放在一起比较。
    \item 特征提取：以时间序列数据为例，可以从一段原始曲线里提取出各种统计量，也可以计算不同时间段之间的差值统计，或者跨样本的统计特征。喷油器项目里，每个检测点采集到的原始曲线正是通过这类特征提取，转换成了模型可以直接使用的数值特征。
\end{itemize}

数据准备好之后，就进入建模阶段。首先要厘清机器学习方法的一个基本分类维度：监督学习和无监督学习。
\begin{itemize}
    \item 监督学习：历史数据里已经知道结果，任务是学一个函数，把输入映射到这个已知结果上，进而用来预测未来的新样本。
    \item 无监督学习：历史数据里的结果是未知的，任务是从数据本身发现规律或模式，比如把相似的对象归到同一类，或者找出变量之间的关联关系（关联分析）。
\end{itemize}
在分类和回归任务下，可选的具体算法有很多：朴素贝叶斯、逻辑回归、K 近邻、支持向量机、决策树、随机森林、梯度提升树、神经网络（分类方向），以及线性回归、广义线性模型、非线性回归、回归树、支持向量回归、LASSO（回归方向）。无监督方向则有层次聚类、划分式聚类、模糊聚类、自组织映射、密度聚类（聚类方向），以及相关性分析、关联规则挖掘（购物篮分析，关联方向）。

针对喷油器项目，决策树或随机森林需要调整树的数量、分裂准则（信息增益比、信息增益、基尼系数、准确率）、最大深度是否剪枝等参数；梯度提升树需要调整树的数量和最大深度。选好算法只是第一步，参数调优同样是一大块工作量。

模型训练完了，还需要一套指标来判断它靠不靠谱。标准做法是用混淆矩阵框架，把预测结果和真实结果交叉对比，划分出四种情况：
\begin{itemize}
    \item \textbf{阳性（TP）}：预测不合格，实际也确实不合格
    \item \textbf{假阳性（Pseudofehlerrate, FP）}：预测不合格，但实际是合格的，伪错误。意味着模型"多疑"，把好产品误判成了坏产品
    \item \textbf{假阴性（Schlupfrate, FN）}：预测合格，但实际是不合格的，这类错误被称为漏检，是更危险的一种错误，意味着有缺陷产品被放过去了
    \item \textbf{真阴性（TN）}：预测合格，实际也确实合格
\end{itemize}
在这四个数字的基础上，可以算出一整套评估指标：
\begin{itemize}
    \item\textbf{精确率（Precision）}衡量被预测为不合格的产品里，有多少是真的不合格
    \item \textbf{召回率（Recall）}衡量所有真正不合格的产品里，有多少被成功抓出来了
    \item \textbf{特异度（Specificity）}衡量所有真正合格的产品里，有多少被正确放行了
    \item \textbf{准确率（Accuracy）}则是预测正确的比例，也就是 (TP+TN) / 全部样本数
    \item \textbf{伪错误率}：FP 占比
    \item \textbf{漏检率}：FN 占比
\end{itemize}
朴素贝叶斯算法在真实喷油器数据上跑出的结果可以说明问题：整体准确率达到 96.15\%，但召回率只有 33.83\%，也就是说，虽然总体判断准确，但真正能抓出来的不合格品其实只占三分之一左右。这说明单看准确率会掩盖问题，必须结合多个指标一起看。

朴素贝叶斯、决策树、随机森林、梯度提升树等多种方法的对比，揭示了一个很典型的现实取舍：漏检率和伪错误率之间存在此消彼长的权衡。想把漏检率压得更低，往往就得接受更高的伪错误率，反之亦然。选哪个模型、定在哪个平衡点，最终要看业务上更能承受哪种代价。

最后一步是把它嵌入实际生产流程。有几条具体策略：减少检测点和检测特征的数量、抽样检测、直接用工艺参数预测质量结果，以及更进一步的过程内在质量预测（在生产过程中就实时预判质量，及早把有问题的产品挑出来，甚至用软件传感器替代部分物理检测环节）。
