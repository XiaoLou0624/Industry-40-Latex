\section{工业 4.0 中的控制技术}

\subsection{控制技术方式}

在传统工厂中，机器主要依赖固定硬件和本地控制。例如一台 CNC 机床、一台机器人、一套 PLC 控制柜，各自完成自己的任务。而工业 4.0 的核心趋势是把这些设备联网、数字化、软件化，使它们能够交换数据、被监控、被优化，甚至在一定程度上自主调整。

我们用 Software Defined Manufacturing (SDM) 来描述这个趋势：工业自动化正在从 hardware-oriented 转向 software-oriented。也就是说，以前重点是专用硬件和固定功能；未来重点是软件模块、虚拟化、云技术、数字孪生、AI 和自适应系统。

早期的控制系统通常是异构环境（heterogene Umgebung）：不同厂商、不同设备各自使用专
用的硬件平台和操作系统，彼此之间兼容性差，集成和维护成本高，而且控制逻辑往往和具体设
备绑定在一起，也就是面向设备的思路。现在的趋势则是同构、基于 PC 的环境（homogene, PC-basierte Umgebung）：越来越多的控制功能运行在标准化的工业 PC 或通用计算平台上，底层硬件差异被操作系统和软件层屏蔽掉，控制逻辑与具体硬件解耦，也就是面向软件的思路。

\subsection{工业控制系统的类型}

\emph{NC 是 Numerical Control，数控，典型对象是 CNC 机床}。NC 是\emph{通过数字进行控制}的方法，常用于工具机、模具加工和机械制造，并追求\emph{高绝对精度}。

\emph{RC 是 Robot Control，机器人控制}，特别是\emph{串联机械臂}。机器人控制的重点是末端执行器或夹爪的空间运动。它需要在关节坐标和空间坐标之间做坐标变换。常用于汽车制造、装配和搬运，重点通常是\emph{高重复精度}，而不一定是像 NC 那样的高绝对精度。

\emph{MC 是 Motion Control，运动控制}。它关注多个轴之间的\emph{同步运动}。比如一条高速包装线中，输送带、切刀、推料机构必须在毫秒级时间内协调，否则产品会错位。

\emph{SPS 是 Speicherprogrammierbare Steuerung}，英语是 PLC。它是自动化中最基础、最常见的控制器。按 DIN EN 61131-3 编程，\emph{处理模拟和数字信号}，采用循环程序执行，\emph{直接连接传感器和执行器}，结构紧凑且鲁棒。它广泛用于制造技术、过程工业和建筑自动化。

\emph{MES 是 Manufacturing Execution System，制造执行系统}。MES 不直接以毫秒级控制电机，而是管理生产执行过程。可以把 MES 理解为车间层面的操作系统：它知道哪个产品在什么工位、完成了什么步骤、用了什么材料、是否合格、下一步该去哪里。

\subsection{控制架构}

我们不能只讲控制器有哪些，还要讲控制功能放在哪里。一个自动化系统通常有人机界面（HMI）、逻辑控制和运动控制三类软件功能。我们把控制架构分成 PC-based、controller-based、drive-based 和 cloud-based。
\begin{itemize}
    \item PC-based 架构把 HMI、逻辑和运动控制集中在一台工业 PC 上。
    \item Controller-based 架构把逻辑和运动控制放在专用控制器中，HMI 则可能运行在单独的面板或 PC 上。这是工业中很常见、很稳健的架构。
    \item Drive-based 架构把一部分逻辑和运动控制下放到驱动器中。减少上位控制器负担，提高局部响应速度。
    \item Cloud-based 架构把功能放到云端。
\end{itemize}

\subsection{NC内部的信息流}

数控系统内部如何从加工任务变成实际轴运动。加工程序首先描述几何轮廓和工艺参数；控制系统解析程序；然后进行轨迹规划、插补、坐标变换；再生成每个轴的设定值；最后驱动器和伺服系统控制电机运动。这里的关键概念是“从抽象几何任务到实时轴控制”的转换。比如程序里写的是刀具从 A 点走到 B 点，但机器真正执行时，需要每个采样周期给 X、Y、Z 轴分别发送位置或速度指令。

\subsection{工业通信技术}
\label{subsec:industrialcommunication}

工业 4.0 不只是机器能动起来，还要求机器之间、机器与上位系统之间能够可靠交换数据。因此就得用到 ISO/OSI 七层模型，并把它和工业通信联系起来。

七层包括：
\begin{enumerate}
    \item 物理层（Physical Layer）
    \item 数据链路层（Data Link Layer）
    \item 网络层（Network Layer）
    \item 传输层（Transport Layer）
    \item 会话层（Session Layer）
    \item 表示层（Presentation Layer）
    \item 应用层（Application Layer）
\end{enumerate}

Ethernet、TSN 属于较底层的数据链路相关技术；IP 位于网络层；TCP/UDP 位于传输层；OPC-UA 属于应用层。

OPC-UA 可以理解为工业系统之间交换数据的标准语言。它解决的问题是：不同厂家、不同控制器、不同软件系统之间如何以统一方式描述和访问数据。控制器中的各种参数如果没有统一语义，每个厂家都用自己的格式，系统集成会非常困难。OPC-UA 提供统一的信息模型和通信机制，使设备数据可以被上位系统读取。

OPC-UA 有两种通信方式：客户端/服务器模式和发布/订阅模式。
\begin{itemize}
    \item 客户端/服务器（Client/Server）基于请求-响应模型。客户端主动发起请求，服务器处理后返回响应。它可靠，但是慢。
    \item 发布/订阅（Publisher/Subscriber）基于消息中间件（Broker）转发数据，发布者不知道谁在订阅，订阅者也不知道数据来自哪个发布者，他们之间是解耦的。它追求低延迟、高吞吐，适合一对多、周期性大规模数据分发的场景。
\end{itemize}

时间敏感网络（TSN, Time Sensitive Networking）的目标是让普通以太网具备确定性通信能力。普通以太网不能保证数据包一定在严格时间窗口内到达。工业控制需要确定性延迟、低抖动和同步。TSN 使工业网络更适合实时控制。传统自动化网络中，实时控制流量与普通流量通常依赖两套并行的网络基础设施，造成成本高、维护复杂。TSN 的意义之一在于实现这两类并行方案的融合：基于标准以太网扩展，使确定性流量与尽力而为流量能够共用同一套物理网络。此外，TSN 实现全网所有节点间的精确时间同步，为分布式控制系统提供统一的全局时钟基准，这是实现确定性调度、保证有界延迟和低抖动的前提。

\subsection{实时}

实时系统的正确性不仅取决于计算结果是否正确，还取决于结果是否在规定时间内产生。即使结果正确，若超过截止时间才给出，在实时系统的意义上也视为失败。实时性由以下四个特征共同刻画：
\begin{itemize}
    \item 及时性（Zeitgerecht）：任务必须在规定的时间限制内完成
    \item 并发性（Simultan）：系统能够同时处理多个任务，且每个任务都各自满足其时间要求
    \item 可预测性（Vorhersehbar）：系统对所有事件的反应时间是可以预先分析和保证的
    \item 可靠性（Verlässlich）：特性要在系统长期、持续的运行中始终得到保持，而非偶尔达标
\end{itemize}
抢占式调度（Preemptive scheduling）中，高优先级任务到来时可以打断低优先级任务。这适合实时控制，因为紧急任务可以及时执行。

非抢占式调度（Non-preemptive scheduling）中，一个任务开始后要运行到主动让出 CPU。这种方式简单但对实时任务不利。

\emph{中断（Interrupt）：当某个紧急事件发生时，处理器会暂停当前正在执行的程序}，转去执行一段中断服务程序（ISR），处理完之后再回到原来被打断的地方继续执行。中断本质上就是一种硬件层面的抢占。不管当前处理器在执行什么任务，只要中断信号一到，就会被强制打断。这和抢占式调度里"高优先级任务可以打断低优先级任务"的思想是一致的，只不过中断是由硬件事件触发，调度是由操作系统的任务优先级触发。
