\section{工业 4.0 中的控制技术}

\subsection{控制技术方式}

工业4.0之前的机器主要依赖固定硬件和本地控制。工业4.0的核心趋势就是把这些设备联网、数字化、软件化，使它们能够交换数据、被监控、被优化，甚至在一定程度上自主调整。

我们用 Software Defined Manufacturing (SDM) 来描述这个趋势：工业自动化正在从 hardware-oriented 转向 software-oriented。
\begin{itemize}
    \item Hardware-oriented: 早期的控制系统通常是异构环境（heterogene Umgebung），也就是不同厂商、不同设备各自使用专用的硬件平台和操作系统，彼此之间兼容性差，集成和维护成本高，控制逻辑往往和具体设备绑定在一起。
    \item Software-oriented: 现在的趋势则是同构环境（homogene Umgebung）：越来越多的控制功能运行在标准化的工业 PC 或通用计算平台上，控制逻辑与具体硬件解耦。
\end{itemize}


\subsection{工业控制系统的类型}
\label{subsec:controltype}

\begin{itemize}
    \item \textbf{数控（Numerical Control, NC）}是\textbf{通过数字进行控制}的方法，常用于工具机、模具加工和机械制造，并追求\textbf{高绝对精度}。
    \item \textbf{机器人控制（Robot Control, RC）}的重点是末端执行器或夹爪的空间运动。它需要在关节坐标和空间坐标之间做坐标变换。常用于汽车制造、装配和搬运，重点通常是\textbf{高重复精度}，而不一定是 NC 那样的高绝对精度。
    \item \textbf{运动控制（Motion Control, MC）}关注多个轴之间的\textbf{同步运动}。比如一条高速包装线中，输送带、切刀、推料机构必须在毫秒级时间内协调，否则产品会错位。
    \item \textbf{存储控制器（Speicherprogrammierbare Steuerung, SPS）}直接连接传感器和执行器\textbf{处理模拟和数字信号}，结构紧凑且鲁棒。
    \item \textbf{制造执行系统（Manufacturing Execution System, MES）}用来管理生产执行过程。它知道哪个产品在什么工位、完成了什么步骤、用了什么材料、是否合格、下一步该去哪里。
\end{itemize}


\subsection{控制架构}

这一小节讲述\ref{subsec:controltype}小节中的这些控制功能应该应用在什么地方，也就是控制架构，分成以下四类：
\begin{itemize}
    \item \textbf{PC-based 架构}把人机界面（HMI）、逻辑和运动控制集中在一台工业 PC 上。
    \item \textbf{Controller-based 架构}把逻辑和运动控制放在专用控制器中，人机界面运行在单独的面板或 PC 上。
    \item \textbf{Drive-based 架构}把一部分逻辑和运动控制下放到驱动器中，减少上位控制器负担，提高局部响应速度。
    \item \textbf{Cloud-based 架构}把功能放到云端。
\end{itemize}


\subsection{工业通信技术}
\label{subsec:industrialcommunication}

机器之间的数据交流离不开 \textbf{ISO/OSI七层模型}：
\begin{enumerate}
    \item 物理层（Physical Layer）
    \item 数据链路层（Data Link Layer）
    \item 网络层（Network Layer）
    \item 传输层（Transport Layer）
    \item 会话层（Session Layer）
    \item 表示层（Presentation Layer）
    \item 应用层（Application Layer）
\end{enumerate}

典型技术：Ethernet、TSN 位于数据链路层；IP 位于网络层；TCP/UDP 位于传输层；OPC-UA 位于应用层。

\paragraph{OPC-UA}

OPC-UA 是工业系统之间交换数据的标准语言。它有两种通信方式：
\begin{itemize}
    \item \textbf{客户端/服务器模式（Client/Server）}：客户端主动发起请求，服务器处理后返回响应。可靠但速度慢。
    \item \textbf{发布/订阅模式（Publisher/Subscriber）}：基于消息中间件（Broker）转发数据，发布者不知道谁在订阅，订阅者也不知道数据来自哪个发布者，他们之间是解耦的。它追求低延迟、高吞吐，适合一对多、周期性大规模数据分发的场景。
\end{itemize}

\paragraph{时间敏感网络}

时间敏感网络（TSN, Time Sensitive Networking）的目标是\textbf{让普通以太网具备确定性通信能力}。普通以太网不能保证数据包一定在严格时间窗口内到达。但是工业控制需要确定性延迟、低抖动和同步。

TSN 可以使工业网络更适合实时控制。实现了节点间的精确时间同步，为分布式控制系统提供统一的全局时钟基准。

\subsection{实时}

实时系统的正确性不仅取决于计算结果是否正确，还取决于结果是否在规定时间内产生。实时性由以下四个特征共同刻画：
\begin{itemize}
    \item 及时性（Zeitgerecht）：必须在规定时间内完成。
    \item 并发性（Simultan）：同时处理多个任务。
    \item 可预测性（Vorhersehbar）：对所有事件的反应时间是可以预先分析的。
    \item 可靠性（Verlässlich）：特性在系统长期持续的运行中始终得到保持。
\end{itemize}

\textbf{抢占式调度（Preemptive scheduling）}：高优先级任务到来时可以打断低优先级任务，适合实时控制。

\textbf{非抢占式调度（Non-preemptive scheduling）}：一个任务开始后要运行到主动让出 CPU，简单但对实时任务不利。

\textbf{中断（Interrupt）}：当紧急事件发生时，处理器会暂停当前正在执行的程序，转去执行一段中断服务程序（ISR），处理完之后再回到原来被打断的地方继续执行。中断和抢占式调度的思想是一致的，只不过中断是由硬件事件触发，调度是由操作系统的任务优先级触发。
