\section{标准与参考架构}

\subsection{标准的重要性}

工业4.0只有依靠统一的规范与标准，收益才能真正被兑现。与此同时，安全本身也是工业4.0一切应用场景得以展开的前提与推动力，安全设计这一原则将会贯穿其中。

从历史的角度看，标准化本身也经历了一个从被动走向主动的转变。早期的标准化更多是对既有产品的事后规范，而后逐渐延伸到对工艺流程的规范，如今则进一步发展为在创新产生的同时就主动展开的标准化工作。

在具体效力层面，规范、标准与事实标准之间存在明显差异，这种差异直接影响着企业所拥有的灵活性。处于金字塔顶端、具有完全共识性质的是各层级的正式标准，包括国际层面的ISO，欧洲层面的CEN，以及国家层面的DIN，其作用在于保障某一领域核心任务的可靠性。居中的是有限共识性质的联盟标准与规范，例如源自工业4.0平台的RAMI与I4.0组件，其作用在于持续提升互操作性。处于底部、由市场与企业自身渗透形成的则是事实标准，例如企业标准与厂内规范（例如Windows系统），其特点是灵活性最大。

\subsection{两大参考架构模型：RAMI 4.0与IIRA}

面对工业4.0所涉及的庞杂议题，如何以一种结构化的方式加以把握，是参考架构模型试图回答的问题。\textbf{德国的RAMI4.0（Referenz Architektur Modell Industrie 4.0）}与\textbf{美国的IIRA（Industrial Internet Reference Architecture）}是两个彼此独立发展、却又出发点各异的代表性方案。

RAMI4.0源自一项\textbf{由政府主导}的工业4.0平台倡议，而IIRA则\textbf{完全由产业界自发推动}。就覆盖领域而言，RAMI4.0\textbf{聚焦生产制造}，对下一代制造价值链给出更为详尽的模型，其定位更偏向纯粹的信息技术架构。\textbf{IIRA的视角横跨能源、医疗卫生、制造、公共部门与交通运输}，进而汇聚到工业4.0所对应的制造领域。

RAMI4.0 的三条轴线中，\textbf{层（Layers）}这一轴描述的是信息在系统中被采集、组织并加以利用的方式，共分六层，自下而上依次为：
\begin{itemize}
  \item \textbf{资产层（Asset）}：物理世界中真实存在的实体，例如机器、工件、文档乃至人；
  \item \textbf{集成层（Integration）}：由物理世界向数字世界的过渡，负责把实体的状态转化为可处理的数字信息；
  \item \textbf{通信层（Communication）}：规定对这些信息的访问与传输方式，对应统一的通信协议与数据格式；
  \item \textbf{信息层（Information）}：承载完成各项功能所必需的数据及其语义描述；
  \item \textbf{功能层（Functional）}：资产所具备的各项功能，以及这些功能得以运行的形式化环境；
  \item \textbf{业务层（Business）}：组织形式与业务流程，把技术能力与商业模式、法律与合同条件联系起来。
\end{itemize}
层这一轴的意义在于说明：一个物理资产要真正成为工业4.0组件，必须逐层向上被集成、被通信、被赋予语义、被功能化，并最终服务于业务流程；任何一层的缺失都会使上层无从建立。由此也可以看出 RAMI4.0 的两个核心价值：
\begin{itemize}
  \item 它把工业4.0 所涉及的全部要素统一收拢进一个由\textbf{层、生命周期与层级等级}共同构成的模型之中，使不同专业背景的参与者能够在同一个坐标系下讨论同一个问题。
  \item 它把原本盘根错节的复杂流程\textbf{切分为一个个可以单独处理的小包}，每个小包都能够被独立地开发、标准化与评估，其中同样\textbf{涵盖了数据保护与信息安全}这两个横贯性的议题。
\end{itemize}

RAMI4.0和IIRA两个架构模型彼此\textbf{不互斥}。RAMI4.0\textbf{聚焦生产制造本身}，IIRA则呈现出\textbf{更强的信息技术}特征；IIRA的功能视角在结构上可与RAMI4.0相对照，但RAMI4.0典型的三条轴线中的\textbf{生命周期与层级}）在IIRA中并未被涉及。IIRA为能源、医疗卫生、制造、公共事务、交通运输等诸多领域提供了一个通用框架，而这些领域并非RAMI4.0所关照的范围；IIRA的优势还在于，其\textbf{每一个视角都与其他软件参考模型保持一致，并尽可能地兼顾数据与流程的安全性}。

进一步看，两者在对待数据的方式上存在根本差异。RAMI4.0 明确把\textbf{资产的生命周期}纳入模型，追求对每一个可唯一标识的工业4.0组件在其整个生命周期内\textbf{持续地采集、维护与扩充}数据和信息，形成一份贯穿始终的数字档案；并且 RAMI4.0 不仅能描述物理设备，也能映射订单这类\textbf{非物质要素}。IIRA 则着眼于\textbf{信息流}的描述，其建模对象限于\textbf{物理对象}，数据\textbf{按需产生}并只服务于既定目的（例如某项大数据分析），并不追求生命周期意义上的长期积累。

RAMI4.0 在描述产品生命周期时，把同一产品区分为\textbf{类型（Type）}与\textbf{实例（Instance）}两个部分。
\begin{itemize}
\item \textbf{类型}对应"开发"与"使用及维护"两个阶段，描述的是资产的类型层面信息——设计开发、结构设计、计算机仿真等等，其数字侧的体现是\textbf{数字孪生}。
\item \textbf{实例}对应"生产"与"使用及维护"两个阶段，描述的是一个具体的、物质性的资产：序列号、过程参数、质量数据，以及维护、服务与回收记录等，其数字侧的体现是\textbf{数字影子}。
\end{itemize}
换言之，一个类型经过生产被实例化为许多个体，此后每个个体各自积累属于自己的数据轨迹；这也正是 RAMI4.0 追求对唯一可标识组件做终身数据积累的具体落点。
